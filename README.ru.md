# Meeting Recorder

**Автоматическая запись аудио онлайн-встреч для Windows: локальная транскрибация, раскладка по проектам и протокол от ИИ.**
[English version](README.md)

Работает с любым сервисом звонков на вашем ПК (Zoom, Google Meet, Microsoft Teams, Яндекс Телемост, Битрикс24, ControlTalk, Discord…): пишет микрофон и системный звук, поэтому ничего не нужно подключать. Видео не записывается.

## Возможности
- **Сам находит звонок** (занят микрофон + окно сервиса звонков) — ничего нажимать не нужно.
- **Правила записи**: *записывать*, *пропускать* или *спросить* — по ключевым словам в названии события календаря, участниках или заголовке окна. Пропускайте встречи, которые сервис уже пишет сам (учёба, заказчик), и записывайте те, где никто не пишет (утренние стендапы).
- **Локальная транскрибация** ([faster-whisper](https://github.com/SYSTRAN/faster-whisper)): аудио не покидает ваш компьютер. Модель выбирается в настройках.
- **Проекты**: встреча попадает в папку проекта по правилу, названию в календаре или словам в разговоре; неясные — в `_Inbox`.
- **Протокол**: *Участники / Итоги / Решения / Задачи / Открытые вопросы* через любой OpenAI-совместимый API (OpenAI, Z.ai, OpenRouter, свой), Anthropic API, локальную **Ollama** или Claude Code CLI. Можно выключить и оставить только транскрипт.
- **Календарь** по секретной ссылке ICS (Google, Яндекс, Outlook) — без OAuth.
- Значок в трее, окно настроек (русский / английский), автозапуск, ключи API шифруются Windows DPAPI.

## Установка
**Установщик:** скачайте `MeetingRecorder-Setup.exe` на странице [Releases](../../releases) и запустите.
**Из исходников** (Python 3.10+, Windows):
```powershell
git clone https://github.com/KimViktor522/meeting-recorder; cd meeting-recorder
python -m venv .venv; .venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python run.py
```

## Первый запуск
1. Откроется окно настроек. Добавьте **проекты** и **правила записи**.
2. Вкладка **«Распознавание»**: выберите модель и нажмите «Скачать» (small ≈ 485 МБ — разумный старт для ноутбука без видеокарты).
3. *(По желанию)* вкладка **«Протокол»**: выберите провайдера, вставьте ключ API, нажмите «Проверить». Вкладка **«Календарь»**: вставьте ссылку ICS.
4. Закройте окно — приложение продолжит работать в трее. Клик по значку снова открывает настройки.

Результат: `<папка встреч>\<проект>\Meetings\<дата>_<название>\` — `audio.m4a` (левый канал — вы, правый — остальные), `transcript.md`, `protocol.md`.

## Как определяется звонок
Запись начинается, только если **одно и то же приложение** держит микрофон **и** владеет окном с названием из списка «Сервисы звонков» (проверяется по exe процесса окна). Папка «Телемост» в Проводнике при микрофоне у VS Code — это *не* звонок.
Что видит детектор во время реального звонка: значок в трее → «Статус и диагностика» → «Что видит детектор», либо `MeetingRecorder.exe --diagnose` (пишет `diagnose.log` в папке данных). Если ваш сервис не определяется, добавьте слово из заголовка его окна в «Сервисы звонков».

## Запуск по приветствию
Необязательно (вкладка «Приветствие»). После определения звонка программа локально слушает звук лёгкой моделью и ничего не сохраняет, пока не услышит фразу вроде «добрый день» или «здравствуйте». Тогда запись сохраняется с начала звонка; если звонок закончился без приветствия, временный звук удаляется. Если приветствия нет N минут — запись начнётся сама (0 — не начинать). Список фраз редактируется.

## Диагностика записи
Значок в трее → **«Статус и диагностика»**: живые уровни микрофона и системного звука, кнопки **«Начать запись» / «Остановить»** (ручная запись сама не останавливается), журнал событий. Во время любой записи приходит уведомление, если микрофон молчит минуту, системный звук — 2 минуты, поток записи остановился или сменилось устройство звука по умолчанию.

## Проверяемый протокол
У каждого решения, задачи и открытого вопроса указано время фрагмента транскрипта: `[12:34]` — ссылка на `audio.m4a#t=754`. Код сверяет ссылки с транскриптом: несуществующие снимает, пункты без источника помечает `⚠ нет источника`, в конце — сводка проверки.

## Импорт готовой записи или транскрипта
Значок в трее → **«Импортировать встречу…»** (или `MeetingRecorder.exe --import call.mp4 --transcript call.vtt --title "Синк" --project Alpha`). Принимает видео/аудио (берётся звук; видео не сохраняется, если не отмечена копия) и/или готовый транскрипт (VTT, SRT, TXT, MD — с таймкодами и именами говорящих или без). С готовым транскриптом распознавание не запускается. Дальше тот же конвейер «проект → протокол» — удобно для встреч, которые ваши правила пропускают, потому что сервис пишет их сам.

## Приватность и закон
- Аудио и транскрипты остаются на вашем ПК. Выбранному провайдеру протокола уходит **только текст транскрипта** (для полной локальности используйте Ollama).
- **Запись разговоров может требовать согласия участников — это зависит от законов вашей страны. Предупреждайте участников. Ответственность за соблюдение закона — на вас.**
- Данные программы: `%APPDATA%\MeetingRecorder` (настройки, журналы). Ключи API и ссылка ICS хранятся в зашифрованном виде для вашего пользователя Windows.

## Ограничения
- Только Windows 10/11; используются устройства звука по умолчанию. Лучше в наушниках (иначе микрофон слышит колонки).
- Говорящие делятся только на «Я / Собеседник», не по людям.
- Звонок определяется по заголовку окна: название сервиса должно быть в списке «Сервисы звонков» (вкладка «Основные»), при необходимости добавьте своё.
